Event-Driven Ansible

From reactive to proactive automation

AAP 2.6 / EDA Controller 1.2.1 — Team Knowledge Share

The Problem

Traditional automation is reactive by request — someone notices an issue, logs in, and runs a playbook.

Problem occurs → Human notices → Human decides → Human runs playbook → Fixed
The Gap

Minutes, hours, or days between problem and response. During that time — outages, SLA breaches, customer impact.

What if the playbook ran automatically the moment the problem was detected?

The Solution: EDA

EDA watches for events in real time and triggers the right response:

Problem occurs → Event emitted → EDA matches rule → Playbook runs → Fixed (seconds)

EDA is an "if-this-then-that" engine for infrastructure, powered by Ansible.

Architecture

StepComponentWhat Happens
1Event SourceExternal system emits event (Alertmanager, webhook, file change)
2Source Pluginansible-rulebook receives and parses the event
3Rules EngineEvent evaluated against all rules in the rulebook
4Condition MatchIf condition is true, the action fires
5Actionrun_job_template calls AAP Controller API
6AAP ControllerLaunches job template on target hosts
7PlaybookRuns remediation/notification on the targets
Key Insight

Your existing playbooks and job templates stay the same. EDA adds the reactive layer on top.

Key Concepts

Rulebook

A YAML file defining source → condition → action. The core of EDA.

Source Plugin

Listens for events: webhook, alertmanager, file_watch, journald, or custom.

Condition

Expression evaluated per event.
event.payload.field == "value"

Action

run_job_template, run_playbook, debug, set_fact, post_event

Decision Environment

Container image for ansible-rulebook. Like an EE but for EDA.

Rulebook Activation

A running instance of a rulebook in EDA Controller. Always listening.

Rulebook Anatomy

Real example from our repo: alertmanager/csr-approval.yml

- name: CSR Auto-Approval on AlertingDegraded
  hosts: all
  sources:                                    # WHERE
    - ansible.eda.alertmanager:
        host: "0.0.0.0"
        port: 8000

  rules:
    - name: Approve CSRs on AlertingDegraded
      condition: >-                           # WHEN
        event.payload.status == "firing" and
        event.payload.alerts[0].labels.alertname == "AlertingDegraded"
      action:                                 # WHAT
        run_job_template:
          name: "NOC - CSR Approval"
          organization: "Default"
          job_args:
            limit: "{{ event.payload.alerts[0].labels.cluster }}"
Source: Alertmanager Condition: AlertingDegraded firing Action: CSR Approval with cluster limit

Creating Your Own Rulebook

5 steps from idea to running activation:

#WhatWhere
1Create the rulebook YAMLrulebooks/<source>/<name>.yml
2Create the playbook (if needed)playbooks/<name>.yml
3Create the job templateAAP UI → Templates (enable Prompt on Launch)
4Push to git, sync projectgit push → EDA UI → Sync
5Create activation, enableEDA UI → Rulebook Activations → Create

Rulebook Template

- name: My New Rulebook
  hosts: all
  sources:
    - ansible.eda.webhook:
        host: "{{ webhook_host | default('0.0.0.0') }}"
        port: "{{ webhook_port | default(5000) }}"
  rules:
    - name: React to my event
      condition: event.payload.type == "my_event"
      action:
        run_job_template:
          name: "My Template"
          organization: "Default"
          job_args:
            extra_vars:
              data: "{{ event.payload.data }}"
